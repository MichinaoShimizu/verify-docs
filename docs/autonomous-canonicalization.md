# 自律正本化モード

`dedupe-docs` は `verify-docs.config.json` の `dedupe.mode` を読む。`safe` は保守的な正本選定、
`auto` は既定の自律正本化モードであり、設定がなければ `auto` とする。利用者またはリポジトリが
`safe` を明示した場合は、保守的な正本選定で実行する。対象・目標・禁止事項が指定されている場合は、
それらを優先する。

## safe モード

`safe` では[正本候補の選定規約](canonical-selection.md)と
[判定と利用者への質問](judgement-and-escalation.md)に従う。

## 自律正本化モード

正本性と読者経路を高めるため、文書間の内容統合、ポインタ化、新たな正本文書と必要な
ディレクトリの作成、統合済み不要文書の削除を行える。意味が重なる範囲や配置先に多少の判断リスクがあっても、
その不確実性を理由に利用者の回答待ちで停止しない。対象内の候補を処理し、検査と記録まで
完走する。無回答の `回答待ち` を残さない。`scripts/select-canonical.mjs` の判定は `safe` の
選定規約に基づくため、自律正本化モードでは実行を要しない。実行した場合も `decision-required`
は停止の理由にせず、本節の規則で正本を決める。

実施前に、元文書、統合先、各文書だけにある対象読者・条件・例外・手順・数値・コマンド・
参照先、正本へ向くリンクを一時作業記録へ列挙する。既存文書のどれも全情報を置く場所として
適さない場合は、既存の文書構成と読者の入口に合わせた新しい正本文書を作る。正本には元文書の
固有情報を統合し、入口文書には必要な導線を残す。

統合先は読者の経路を保つように選ぶ。入門・チュートリアルのように一続きで実行する手順を
別文書へ移すと、読者が手順の途中で離れることになる。この場合は手順を残す側を正本にし、
他方をポインタにする。概観・用語集のように、各節の冒頭で正本へリンクしつつ1〜2文で定義する
形は、逐語一致・手順・数値の重複がない限り統合しない。
読者が各ページへ個別に到達する文書群で、ページ冒頭に置く前提文書への短いポインタ（「このページは
〜を前提にしています」）は、ページごとに必要なため統合しない。検証器が重複と報告する場合は、
文言を短くして検出を避けず、保護対象として記録して作業単位の基準で確認する。
同じ層の並行する参照ページ（API の書き方ごとのリファレンスなど）の重複は統合してよいが、
ガイドとリファレンスのように層が違う文書の言い換えは、読者が別々に到達するため統合しない。

正本に内容を移すと、すでに上限を超えている正本が基準時より大きくなり、新たな違反になる。
この場合は小さい側を正本にするか、移す内容を最小にし、それでも超える場合は文書サイズ例外に
理由を記録する。上流の原文と同期して保守する翻訳文書は、構成を変えると同期が崩れるため統合の
対象にしない。同期しているかの判断は自律圧縮モードと同じ根拠による。

新しい正本を既存のどのディレクトリにも適切に置けない場合は、既存の文書配置規約に沿う
リポジトリ内の適切な場所に必要なディレクトリを作成できる。`excludePaths` に含まれる
領域には作成しない。既存の分類と同じ話題・読者・粒度に合う親ディレクトリを優先し、
親直下では同階層の文書群と混ざるときだけその配下に作る。リポジトリ直下の新しい分類は、
既存のどの分類にも属さず、独立した話題または読者経路を持つ場合に限る。単にファイル名を
迷うため、または既存の分類に無理なく置けるために、ディレクトリを新設しない。

新設した正本は、既存の入口文書または親ディレクトリの索引から到達できるようにする。既存の
構成が索引を使わない場合は、その構成にある読者経路から到達できるリンクを更新する。新設した
ディレクトリのパス、選んだ親ディレクトリ、既存の候補を選ばなかった理由、統合元、入口からの
経路を一時作業記録へ残す。

不要文書を削除できるのは、次を全て満たす場合だけである。

- 削除対象だけにあった情報を正本へ統合済みである
- 正本または残すポインタへ向けて、削除対象へのリンクと断片リンクを更新済みである
- 削除しても対象読者の入口と必要な導線を失わない
- `node scripts/document-structure-verifier.mjs` でリンク切れ・孤立文書・サイズ超過・
  機械的重複がない

自律正本化モードでも、事実を捏造しない。法的・安全上の注意、契約上の義務、利用者が明示した
数値・コマンド・設定値は削除・変更しない。`allow-duplicate` マーカーを自分で追加せず、
対象外の文書を変更しない。これらを守ったまま統合できない情報は残し、未完了にはせず理由を
記録する。

統合・削除の後、`node scripts/check-preserved-content.mjs --base=<開始コミット>`（[作業単位の基準](work-record-lifecycle.md#作業単位の基準)）を実行し、
正本へ移したつもりで失われたコードブロック・コードスパン・URL がないかを確かめる。列挙された
項目は正本へ戻すか、残さない理由を一時作業記録に書く。

一時作業記録と保守報告に `実行モード: 自律正本化`、元文書、正本、作成・削除した文書・
ディレクトリ、移動した内容、残したリスク、保護対象、最終検査結果を記録する。全対象を統合、ポインタ化、
削除または保護対象として記録し、`node scripts/document-structure-verifier.mjs` が
「文書構造: すべて通過」で終われば完了とする。既存違反がある文書群では、`dedupe-docs` の
`SKILL.md` の完了基準に従い `--baseline` で新規違反がないことを確認する。

`safe` モードとの正本化・削除・必須事実の結果を比べる場合は、同じ入力スナップショットから
[モード比較](mode-comparison.md)を実施する。
