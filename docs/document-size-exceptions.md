# 文書サイズ例外一覧の形式と運用

[文書構造の是正手順「4. 文書サイズ例外の記載」](remediation.md#4-文書サイズ例外の記載)・
[文書構造検証設定](config.md#文書構造検証設定)から参照される。文書サイズ例外一覧の形式・運用ルールを
確認する際に参照する。

| 項目 | 値 |
| --- | --- |
| 和名 | 文書サイズ例外一覧 |
| 英名 | DocumentSizeExceptionList |
| ファイル名 | `document-size-exceptions.json` |
| リポジトリ内パス | `document-size-exceptions.json` |
| 配布先パス | `document-size-exceptions.json` |

上限を超過しているが現時点では分割できない文書の申告リスト。パッケージ内の
一覧は自己検査用であり、導入器は配布先へコピーしない。検査から除外するのではなく、
認めた上で毎回の実行結果に出力し続ける仕組み。

```json
[
  {
    "path": "docs/deploy.md",
    "reason": "初期設定と独自ドメインの節がまだ混ざっている",
    "section": {
      "headingPath": ["デプロイ", "独自ドメイン"],
      "startLine": 42,
      "endLine": 118,
      "bytes": 4812
    }
  }
]
```

- `path` はリポジトリ直下からの相対パス。検査対象に存在しないパスを
  記載すると「この文書は既に存在しない」で検査が失敗する（削除漏れの
  検知機構）
- `reason` は必須の空でない文字列で、残存理由を追跡できるようにする
- 各要素には `path`・`reason` と任意の `section` だけを指定し、同じ `path` を重複させない
- `section` は任意。`--init-size-exceptions` が出力する、最も大きい末端節の見出し階層・行範囲・
  サイズを残せる。文書全体の上限超過を免除する仕組みは従来どおり `path` 単位であり、
  `section` は分割対象を曖昧にしないための作業上の目印である
- 絶対パスや `..` を含むパスは指定できない
- 是正後は削除する。上限内に収まった文書がなお記載されていると「既に
  上限内に収まっている」で検査が失敗する

手動でも記述できる。既存文書がまとめて上限を超過しているリポジトリへの初回導入時は、
`node scripts/document-structure-verifier.mjs --init-size-exceptions` でその時点の違反を一括で
書き出してから運用を開始してよい。
以降は新規文書・追記文書から上限を遵守し、文書サイズ例外一覧は削減する方向に
のみ運用する。際限なく増やすと、肥大化検知が負債を許容する仕組みに変わる。導入直後より
件数が増えていれば退行の目安となる。
