# 自律圧縮モード

`tighten-docs` は `verify-docs.config.json` の `tighten.mode` を読む。`safe` は意味保持モード、
`auto` は既定の自律圧縮モードであり、設定がなければ `auto` とする。利用者またはリポジトリが
`safe` を明示した場合は、意味保持モードで実行する。対象・目標・禁止事項が指定されている場合は、
それらを優先する。
どちらのモードでも、導入した verify-docs 一式（`verify-docs`・`dedupe-docs`・`tighten-docs` の
スキル）は、それ自体を改善する作業でない限り対象に含めない。上流の原文と行や段落を揃えて
保守する翻訳文書は、自律圧縮すると同期が崩れるため、意味保持モードにするか対象から外す。
同期して保守しているかは、リポジトリ内の根拠（上流のコミットや原文の行番号を記録する仕組み、
翻訳手順を定めた文書）で判断し、根拠がなければ通常の文書として扱い、その判断を記録する。
表示を切り替える別々のブロック（API の書き方ごとの説明など）に同じ文があるのは重複ではない。

## 意味保持モード

意味、対象読者、条件、手順の順序、免責文言を保てると確信できない候補は変更せず、
利用者に質問する。質問には候補箇所へのリンク、削減案、失われるおそれがある内容、
変更する場合と残す場合の影響を含める。回答があるまで候補を是正済みにせず、保守報告へ
統合しない。

## 自律圧縮モード

多少の意味変更リスクがある削除・結合・言い換えも、ファイルサイズを減らすために実施する。
この不確実性を理由に利用者の回答待ちで停止せず、対象内の候補を処理して圧縮、検査、記録まで
完走する。候補を無回答の `回答待ち` として残さない。

ただし、事実を捏造しない。リンク・断片リンクを壊さず、Markdownとしての成立を保ち、文書間の
内容移動・正本化には広げない。法的・安全上の注意、契約上の義務、明示された数値・コマンド・
設定値は、削減が必要でも削除・変更しない。これらを守ったまま圧縮できない箇所は残し、未完了
にはせず理由を記録する。

言い換えでは表現だけを短くし、命題を減らさない。次は削らず、言い換え後にも残っているかを
1文ずつ確かめる。

- 理由・目的と、2つ目以降の帰結（「X なので Y する」「A し、B を促す」の X・B）
- 手順の順序や前提を示す節（「これで〜できたので」「〜を読んだ後で」）
- 条件・限定・対象を絞る語（「〜の場合」「〜がある場合だけ」「手動で」「〜へのパス」）
- 義務の強さ（「してよい」「すべき」「しなければならない」、英語の may・should・must）と、
  確からしさ（「かもしれない」を断定にしない）
- 「重要」「注意」などの注意書きと、「〜ことに注意してください」のように読者の注意を促す文。
  同じ文書の別の箇所に同じ内容があっても、完全に同じでない限り残す

コードブロック、出力例、テンプレート指令（`{{ }}`・`{% %}`）、front matter も保護対象とする。
削除してよいのは、同じ文書内に完全に同じものがある場合だけである。コードスパンや文章への
置き換えも削除として扱う。一部を省略する場合も、
コードブロックの言語として成立する形を保つ。コードブロックから削った量は、文章から削った量と
分けて記録する（大きな出力例を削っただけで削減率が高く見えるのを防ぐため）。

圧縮後、`node scripts/check-preserved-content.mjs --base=<開始コミット>`（[作業単位の基準](work-record-lifecycle.md#作業単位の基準)）で、開始時にあった
コードブロック・コードスパン・URL がどこかに残っているかを照合する。列挙された項目は復元するか、
同じ文書内の完全な重複だったなど削除した理由を一時作業記録に書く。

一時作業記録と保守報告に `実行モード: 自律圧縮`、変更箇所、残したリスク、変更しなかった
保護対象、最終検査結果を記録する。対象内の候補を処理済みまたは保護対象として記録し、
`node scripts/document-structure-verifier.mjs` が「文書構造: すべて通過」で終われば完了とする。
既存違反がある文書群では、`tighten-docs` の `SKILL.md` の完了基準に従い `--baseline` で新規違反がないことを確認する。
圧縮しても上限を超える文書は分割が必要な文書として一時作業記録と保守報告に記し、次の
`verify-docs` の工程へ引き継ぐ。`tighten-docs` は文書を分割しない。

`safe` モードとの圧縮率や必須事実の欠落を比べる場合は、同じ入力スナップショットから
[モード比較](mode-comparison.md)を実施する。
