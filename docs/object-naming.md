# オブジェクトの名称・参照規約

文書構造是正スキルから参照される。和名・英名・ファイル名を
組にして定義するオブジェクトを、文書群で同じ呼称として扱うための規約である。

## 対象

対象は、導入先で直接実行・設定・参照・生成する運用オブジェクトに限る。公開する
共有モジュールは、文書で構成要素として説明する場合に対象へ含める。和名だけを持つ
一般概念、ファイルを持たない JSON の値、コマンド中のパスそのものには適用しない。

テスト（`*.test.mjs`）、fixture、評価データ、ベンダー同梱物、生成元を持たない
一時ファイルは対象外とする。これらは動作確認や実装の補助であり、導入先が呼称を
選んで利用する運用オブジェクトではない。

## 定義文書での記載

オブジェクト自体を定義する文書では、対象の説明より前に、次の3項目を表または同じ情報を
持つ箇条書きで一組として示す。
リポジトリ内の正本と導入先の配置が異なる場合は、続けてリポジトリ内パスと
配布先パスも示す。

| 項目 | 記載する値 |
| --- | --- |
| 和名 | 日本語の正称 |
| 英名 | 識別子・製品名などの英語の正称 |
| ファイル名 | 拡張子を含む basename |
| リポジトリ内パス | このリポジトリで管理する正本の相対パス |
| 配布先パス | 導入後の対象リポジトリでの相対パス |

リポジトリ内に実体がない設定や、導入先へ常設配置しない導入器は、その項目に
「なし」と理由を記す。後続の本文では和名で呼ぶ。英名とファイル名を本文で繰り返さない。

## 他文書からの参照

定義文書以外では、和名を正称とする。初出だけでなく、オブジェクトを指す呼称は
常に、定義文書の該当箇所へリンクした和名で記載する。

```md
[文書構造検証器](verification-boundaries.md#検証器とプレイブックの責務)
```

英名・ファイル名を呼称として併記したり、他文書で3項目を再定義したりしない。
ただし、実行手順のコードブロック、設定例、実在性を示すパスのように、ファイル名
そのものが必要な箇所ではバッククォート内に記載してよい。この例外は、呼称を英名・
ファイル名へ切り替えることを意味しない。
