# LLMによる日常的な文書変更

`verify-docs` は、LLMがMarkdown文書を追加・更新・削除・レビューする回に必ず使う。
目的は、文章の内容を一律に書き換えることではない。変更によって参照、到達経路、
文書サイズ、同一段落の重複を壊していないことを確認する。

コードだけを変更し、Markdownを読まず作らず変えない回は対象外とする。対象となる
Markdownには、README、CLAUDE.md、AGENTS.md、`docs/`、スキルの`SKILL.md`のほか、
リポジトリ内で追加、更新、削除する`.md`ファイルを含める。

導入器は、ルートの`AGENTS.md`へこの規約を管理ブロックとして追加する。`CLAUDE.md`には
`@AGENTS.md`の取り込みを追加するため、Claude Codeでも同じ規約を読む。既存の本文は残し、
管理ブロックが壊れている場合は導入を停止する。

## 軽量確認

通常の作成、更新、レビューでは、完全是正の作業記録を作らない。変更前に対象ファイルと
依頼に関係する入口文書・規約を確認し、変更後に次を実行する。

```bash
node scripts/document-structure-verifier.mjs
```

通過した場合は、実行結果を完了報告に含める。既存の違反がある場合は、変更で増えたか、
変更前からあるかを区別して報告する。未コミットの変更は`--changed-base`の差分に含まれない
ため、作業中の確認を差分検査だけで済ませない。

PRを作るなど、基準ブランチとの差分だけを判定したい段階では、全体検査に加えて次を使う。

```bash
node scripts/document-structure-verifier.mjs --changed-base=origin/main
```

## 完全是正へ昇格する条件

次のいずれかに当たる場合は、軽量確認で終えない。文書構造是正スキルの作業記録・再検証・
保守報告の手順を実施する。

- 文書を追加、移動、分割、削除し、リンクまたは読解の経路を変える
- 複数のMarkdown文書、入口文書、またはスキルを同時に更新する
- 検証器が参照切れ、孤立、サイズ超過、完全一致重複を報告する
- 利用者が文書群の監査、構造是正、重複解消、または簡潔化を依頼する

## 無駄を減らすレビュー

文書レビュー、複数のMarkdown文書の追加・更新・削除、または検証でサイズ超過・重複が
見つかった回は、次の順に実行する。

1. `verify-docs`で構造上の違反を確認する
2. `dedupe-docs`で文書間の意味的重複を確認し、正本とポインタを決める
3. `tighten-docs`で意味を保ったまま冗長な表現と不要な節を減らす
4. `verify-docs`で、変更後のリンク・到達性・サイズ・完全一致重複を再検証する

`dedupe-docs`と`tighten-docs`は安全モードで実行する。数値、条件、手順の順序、免責文言を
保てると判断できない候補は変更せず、利用者へ質問する。自律正本化・自律圧縮は依頼で
明示された場合だけ使う。

## 反復検証

文書を変更した工程の直後に`verify-docs`を再実行する。違反が残った場合は、検出結果を
その工程の作業記録へ反映し、違反を生んだ工程へ戻る。通過するまで次の工程または完了報告へ
進まない。意味の保持、正本選定、削除可否を判断できないために止まる場合は、違反を隠したり
例外化したりせず、利用者へ質問する。

無駄を減らすレビューでは、上の一巡を一度で終えない。各巡で変更したMarkdownのパスと
サイズ変化を作業記録に残し、次の巡のdedupe-docsとtighten-docsの対象にする。文書の変更が
なく、`verify-docs`が通過した時点で収束とする。同じ候補が繰り返し残り、意味保持・正本性・
削除可否を判断できない場合は、変更しない理由と質問を記録して利用者へ質問する。

## 大量文書の検証

Markdownが100文書以上ある場合も、`verify-docs`は対象リポジトリの全Markdownを開始時と
完了時に検証する。任意の抽出、先頭だけの確認、または一部の読解単位の通過を、全体の
完了として扱わない。

LLMが読む対象は100文書以下の読解単位に分けてよい。各単位のパス、開始時点と最終の
文書数・合計バイト数、確認済みの候補を一つの作業記録へ追記する。`dedupe-docs`では、
単位をまたぐ候補を同じ候補台帳で比較する。単位ごとの重複解消だけで、文書群全体に
意味的重複がないとは報告しない。

完了報告では、全体の文書数、読解単位数、開始時と最終の合計バイト数、全件の最終検証
結果を示す。性能を評価する場合は、実文書を複製せず合成コーパスで構造検証器を測る。
自律モードを既定候補として確認する場合は、`--tighten-mode=auto --dedupe-mode=auto` を使う。
この測定は `auto` 設定の受理と構造検証の安定性を確認するだけであり、自律的な意味判断や
正本選定の品質は採点しない。

## 完了報告

完了報告では、変更したMarkdownのパス、実行した検査、結果を示す。完全是正では、これに
加えて保守報告のパスと、判断が必要で未解決の項目を示す。検証器の通過は構造上の条件だけを
確認する。文章の正確性、意味的な重複、配置の妥当性を保証するものではない。
