# エージェントによる文書保守の実行

`dedupe.mode` と `tighten.mode` は、単独でMarkdownを編集するCLIの設定ではない。Codex、Claude
Code、Kiroなどで `verify-docs` を起動したエージェントが、この規約に従って編集まで実行する。

## 起動と完走

Codex Appでは `@verify-docs`、Codex CLI/IDEでは `$verify-docs`、Claude Code/Kiroでは
`/verify-docs` を起動する。Markdownの追加・更新・削除・レビューでは、次を完走する。

1. 対象Markdownと入口文書を列挙し、全件の構造検証を実行する。
2. `dedupe-docs` で重複候補、正本、統合元、固有情報、リンク更新を変更計画へ記録する。
3. エージェントが変更計画に従い、正本化、ポインタ化、必要な内容統合、許可された削除をMarkdownへ適用する。
4. `tighten-docs` で同一文書内の冗長な節・段落を編集し、開始・最終バイト数を記録する。
5. 数値、コマンド、設定値、法的・安全・契約上の注意、対象外ファイルを照合する。
6. `verify-docs` を全件再実行する。違反または保護対象の欠落があれば、その変更を是正して再実行する。
7. 正本、削除、圧縮量、残したリスク、最終検査結果を保守報告へ統合する。

設定を `auto` にしただけで完了とはしない。エージェントが文書本文を編集し、再検証と報告を
終えた場合だけ自律実行と報告する。

## safe と auto

導入時の既定は `auto` である。意味を変えない確認を優先する利用者またはリポジトリは、
`verify-docs.config.json` で個別に `safe` を選ぶ。

`safe` は意味、対象読者、条件、例外、手順順序を保てると確信できない候補を変更せず質問する。
`auto` は質問待ちを理由に停止しないが、構造検証、対象外変更の禁止、数値・コマンド・設定値・
法的・安全・契約上の注意の保護を解除しない。
