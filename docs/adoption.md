# 導入と運用

[README.md](../README.md)から参照される。既存リポジトリへの導入、CIへの
組み込み、`document-size-exceptions.json`の運用を扱う。

## 既存のサイズ超過文書への導入

既存文書では、導入初日にすべてを分割できないことがある。その場合は、
例外を明示しながら2段階で導入する。

先に[README.md「導入」](../README.md#導入)に従ってインストールする。

### 1. 現状の違反を一括で申告する

```bash
node scripts/document-structure-verifier.mjs --init-size-exceptions
```

サイズ上限を超えている文書を全て`document-size-exceptions.json`に書き出す。
これらのサイズ超過は例外扱いとなり、検査結果の一覧には出続ける。リンク切れ・孤立・重複など
他の違反は例外にならないため、別途是正する。

### 2. CIに組み込む

以降、新規に書く文書・追記する文書は上限を遵守する。文書サイズ例外一覧に記載された文書は
任意のタイミングで分割し、是正後にエントリを削除する。分割手順は
[文書構造の是正手順「2. 肥大化文書の特定」](remediation.md#2-肥大化文書の特定)
を参照する。

重複はサイズ超過と異なり例外化しない。導入時に検出された場合の是正方法は
[文書構造の是正手順「3. 重複特定」](remediation.md#3-重複特定)
を参照する。

## 初回検査で多い違反

既存リポジトリでは、導入直後の検査で次の違反がまとまって出ることが多い。
文書の欠陥ではなく検査範囲の問題であるものは、`excludePaths` で対象から外す。

| よく出る違反 | 典型的な原因 | 対処 |
| --- | --- | --- |
| 重複が大量に出る | 版ごとの文書の複製（`website/versioned_docs/` など） | 複製側のディレクトリを `excludePaths` に加える |
| 重複が大量に出る | パッケージごとの `CHANGELOG.md` に同じ変更が並ぶ | `CHANGELOG.md` を `excludePaths` に加える |
| リンク切れ・孤立が大量に出る | テスト用の文書（`__fixtures__/` など）や生成物 | そのディレクトリを `excludePaths` に加える |
| リンク切れが大量に出る | 静的サイト生成向けの拡張子なしリンク（`./guide`）やサイトルート基準のリンク（`/guide/`） | 検査はリポジトリ内でたどれるパスだけを正とする。`guide.md` のような実在するパスへ書き換える |
| 孤立が大量に出る | サイドバー設定など、Markdown 以外からだけ到達する文書 | 入口文書か索引文書からリンクする |

`excludePaths` の項目は、`node_modules/` と `.git/` を除き、リポジトリ直下からの
位置で照合する（[検査対象と設定方針](scan-targets.md)）。
