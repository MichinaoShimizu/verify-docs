# 正本候補の選定規約

意味的に重なる二つの記述から正本を選ぶときに使う。文書の新しさ、文字数、参照数だけでは正本を決めない。古い入口文書が参照を集めている場合や、短い案内文が詳細文書を省略している場合があるためである。

ここで定める自動選定の範囲は `dedupe.mode` が `safe` の `dedupe-docs` に適用する。`auto`（既定）では、
[自律正本化モード](autonomous-canonicalization.md)の統合・作成・削除規則に従う。
正本とポインタを、必要な文書だけを段階的に読める構造へ置く規則は
[段階的な文書探索の規約](progressive-disclosure.md)に従う。

## 自動で正本を選べる条件

候補Aを正本、候補Bをポインタにできるのは、次を全て満たす場合に限る。

1. AとBに同じ項目の異なる値がない。
2. Bだけにある対象者、条件、例外、手順、数値、コマンド、参照先がない。AがBの事実を全て含む。
3. Aが明示的な正本であるか、Aが詳細文書でBが入口文書である。
4. BをAへのポインタに置換しても、リンク、断片リンク、対象読者の導線を失わない。

この条件を満たす場合でも、内容を要約・言い換えしない。BはAへのポインタだけに置換する。

## 自動選定しない条件

次のいずれかがある場合は、`decision-required` として利用者に質問する。

- 両方にだけある対象者、条件、例外、手順、数値、コマンド、参照先がある。
- どちらも入口文書、またはどちらも詳細文書であり、明示的な正本がない。
- Bをポインタにすると、Bの読者が必要な導線を失う。
- 同じ主張に見えるが、包含関係を確認できない。

質問には、比較箇所、各候補だけにある事実、推奨する配置先、正本化と重複維持の影響を含める。回答があるまで、候補を是正済みにしない。

## 値が矛盾する場合

同じ項目に異なる値がある場合は、`conflict` として扱う。更新日時や参照数から一方を選ばない。どちらが正しい値かを利用者または当該項目の責任者に確認する。

## 判定器への入力

`scripts/select-canonical.mjs` は、候補ごとに次の情報を受け取る。

```json
{
  "left": {
    "id": "entry",
    "path": "README.md",
    "role": "entry",
    "facts": { "purpose": "パッケージを導入する。" }
  },
  "right": {
    "id": "guide",
    "path": "docs/install.md",
    "role": "detail",
    "facts": {
      "purpose": "パッケージを導入する。",
      "command": "bash install.sh"
    }
  }
}
```

`facts`は、比較した候補から人またはエージェントが取り出した事実である。判定器は事実の意味を推測しない。値が一致するか、片方だけにあるかを判定する。

```bash
node scripts/select-canonical.mjs candidate-pair.json
```

出力は`auto-canonical`、`decision-required`、`conflict`のいずれかである。`auto-canonical`だけをポインタ化の候補にできる。
