# 段階的な文書探索の規約

文書群の正本化とポインタ化は、重複を減らすことだけを目的にしない。開発者または
LLM が現在の作業に必要な文書だけを読み、関係のない詳細・履歴・別の読者向け文書を
最初から読まなくてよい構造にする。

## 文書構造が崩れる型

生成AIエージェントはセッション開始時に CLAUDE.md・AGENTS.md・README を読み、
作業中に関連する docs や `.agents/skills/*/SKILL.md` を参照する。この設計が
崩れると、関係ない決め事まで毎回トークンを消費する。崩れ方は3種類。

1. **入口の肥大化。** CLAUDE.md・AGENTS.md・README に不要な詳細が残ると、
   毎回それを読むことになる
2. **個々の文書の肥大化。** 話題ごとの区切りがあっても、1文書の中身が
   増え続ければ読む量が膨張する
3. **同一説明の重複。** コピー後に片方だけ更新すると矛盾した説明が残る
   （文書分割時にも起きやすい）

## 入口文書の役割

README・AGENTS.md・CLAUDE.md・ディレクトリの索引・SKILL.md は、読者が次に読む
正本を選ぶ入口である。必須要件を除き、入口には次の三つだけを置く。

- 読者または作業の対象
- その正本を読む条件
- リンク先で得られる情報

たとえば「設定値を変更する場合は、設定の正本を読む」のように、読者が自分に必要な
分岐を選べるように書く。入口に、リンク先の手順・理由・設定値を要約して再掲しない。
ただし、リンク先を開かなくても次の文書を選べない入口は不十分である。

## 正本文書の役割

正本は、一つの読者経路または一つの判断・手順に必要な情報を持つ。冒頭で対象読者と
扱う範囲を示し、前提が必要なら前提の正本へリンクする。別の判断・手順・例外を必要と
する読者には、その条件と次に読む正本を示す。

同じ内容を複数の正本に分けない。一方で、利用条件が異なる詳細を一つの正本に集めて、
通常の読者に例外や履歴まで読ませることもしない。内容を移すときは、元文書を短い
ポインタにし、移動先を読む条件と移動先で分かることを残す。

## 文書の分割と配置

文書を分割するのは、同じ読者が同じ判断を行うために常に一緒に読む情報ではなくなった
ときである。たとえば、初回導入、一回ごとの実行、設定変更、実装の改修、過去の経緯は、
それぞれ必要になる条件が異なる。

新しい正本は、同じ話題・読者・粒度の文書があるディレクトリに置く。入口または親の
索引から、新しい正本へ到達できなければならない。複数の経路から参照される詳細は、
それぞれの入口で内容を複製せず、同じ正本へリンクする。

## 変更時の読解経路の点検

文書を新設、分割、移動、統合、ポインタ化するときは、変更に関係する読者経路を一つ
以上選び、入口から作業完了までに読む文書を列挙する。各経路について、次を確認する。

- 入口だけで、次に読む正本を選べる
- 経路上の各文書は、その作業の次の判断または操作に必要である
- 前提、例外、詳細、履歴は、必要になった時点でだけ参照される
- 経路外の文書にしかない必須情報がない

この点検は、サイズ・リンク・文字列重複の機械検査では代替できない。対象読者、必要な
情報、入口からの経路を一時作業記録に残す。正本の選定に迷う場合だけ、
`.agents/skills/dedupe-docs/SKILL.md` の判断規約を読む。

## 導入先リポジトリでの実行経路

導入先の `AGENTS.md` に「文書の分割・移動・正本化・ポインタ化」の入口があれば、そこから
この規約を読む。作業の種類によって、続けて読む文書を次のように選ぶ。

| 作業 | 続けて読む文書 | この時点で読まない文書 |
| --- | --- | --- |
| 分割・移動・ポインタ化だけを行う | `.agents/skills/verify-docs/SKILL.md` と [文書構造の是正手順](remediation.md) | 導入手順、CIの詳細、意味的重複の判断規約 |
| 言い換えを含む重複を統合する | `.agents/skills/dedupe-docs/SKILL.md` と、そこから参照される正本候補の選定規約 | 導入手順、CIの詳細 |
| パッケージを導入または通常利用する | `README.md` | この規約と保守用の判断規約 |

最初の経路で、意味的に重なるか、どちらを正本にするかを判断する必要が生じた場合だけ、
文書重複解消スキルと正本候補の選定規約を追加で読む。文書構造の検査結果を解釈するだけ
なら、`scripts/document-structure-verifier.mjs` 冒頭の説明を読む。
